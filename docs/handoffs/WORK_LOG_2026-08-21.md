## 6. Live references to deleted infrastructure — fixed

Three were real pointers at hosts and folders that no longer exist:

1. **`server/.env.example`** shipped
   `ALLOWED_ORIGINS=https://gloobal.netlify.app` — a deleted site — and its
   comment claimed that was also the code default. It is not: `server.js`
   defaults to `gloobalv3.netlify.app`. Copying that example into the Render
   environment would have **cut the live frontend off from the API**, and a
   CORS rejection reads from the browser exactly like the backend being down.
2. **`server/server.js`** — `getWebAuthnConfig` fell back to
   `https://gloobal.netlify.app` when a request carried no `Origin` header,
   deriving an `rpID` for a domain nobody serves. Unreachable from a browser,
   but a live pointer at dead infrastructure.
3. **`docs/architecture/backend-architecture-report.md`** described the
   frontend and API as living in two repositories and named both incorrectly.
4. **`.claude/skills/prototype-integrator/SKILL.md`** named
   `D:\Desktop\Gloobal` as the main repo. That skill loads into live sessions,
   so it was actively steering work into superseded folders.

Plus 18 operator-facing path corrections: twelve scripts and tests printed
`this test needs Backend/.env`, and six files carried a first-line label
claiming they lived under `Backend/`.

Historical `Backend/` references in comments elsewhere were left alone — they
explain where code came from and are not instructions to follow. Nothing in
`archive/` or the dated handoff/report documents was touched.
